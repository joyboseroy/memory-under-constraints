# E05 results, v0.1: what a first pass shows (and does not)

This is a reduced, pure-NumPy first pass of the E05 design in `e05_dyna_spec.md`. It covers the count and SDM
memories only. The LSTM and Transformer are not built, the grid is a subset, nothing is tuned per arm, and the pilot
gate (E01 and E02 with the neural models) has not been cleared. Read it as an early look at whether the design is
worth the full build, not as a test of the hypotheses as specified. The raw rows are in `results/e05/`. Everything
below is regenerated by `python analysis/e05_summary.py results/e05`.

## What was run

* Environment: steerable context-tree MDP, 4 tokens, order 3, so 64 states by 4 actions. About 10 percent of
  (state, next token) pairs reward. gamma = 0.9. Phases (0, 1, 0) of 2000 steps. Exact value iteration gives the optimal
  and random-policy reward rates per regime.
* Main grid: c in {0.3, 0.6, 0.9} by drift kind in {dynamics, reward, both} at drift_frac 0.5, n_plan in {5, 20, 50},
  5 seeds (every seed is a new MDP), memory tier small. 45 MDPs, 8 arms.
* Severity: drift_frac 1.0 at c = 0.6, 3 seeds. Tier check: small versus medium, count, SDM and replay, c = 0.6,
  dynamics and reward drift, 5 seeds.
* Score: normalised return, (reward rate minus random policy) / (optimal minus random), per phase and overall.
  Adaptation time: first step where a 200-step rolling score reaches 0.5, capped at the phase length.
* Budgets: the count model, the SDM and the replay buffer are matched on `param_bits` within about 0.5 percent per tier.
  The tabular Q table (8192 bits) is a fixed cost shared by all arms and reported separately.
* Statistics: paired differences within the same MDP, mean +/- 1.96 standard errors over those MDPs (15 for a
  per-kind comparison, 45 for an all-grid comparison). The MDPs are shared across n_plan, so the intervals are rough.

## Headline findings

1. **Action conditioning is what makes the memory useful.** The count model without the action in its keys
   (`dyna_count_noaction`) scores 0.18 against 0.52 with it, below plain Q-learning (0.35), and it gets worse as
   planning increases (0.26, 0.18, 0.10 at 5, 20 and 50 planning steps). Planning with a model that cannot see the
   action does active harm.
2. **Most of the remaining gap is coverage, not model accuracy.** A perfect dynamics model that plans only over
   visited (s, a) pairs reaches 0.56, only 0.04 above the count model (+0.040 +/- 0.025, a small gap whose interval excludes zero). The same perfect model allowed to plan over all pairs reaches 0.74, 0.18 higher. In a single-seed diagnostic about half of the
   Q table (123 of 256 pairs) was never visited in 1500 steps under visited-only sampling. This is a property of the planning rule the spec
   prescribes, not of any memory.
3. **A learned model beats replay and plain Q-learning, but an uncompressed table with the same backups nearly ties
   the count model.** Overall: count 0.518, `replay_sa` 0.489, replay 0.424, Q-learning 0.350, SDM 0.444. Paired
   differences: count minus replay +0.094 +/- 0.025, count minus `replay_sa` +0.029 +/- 0.019. Under reward drift
   specifically (phase 1), count beats Q-learning by +0.29 +/- 0.08 and replay by +0.12 +/- 0.06, and ties
   `replay_sa` (+0.03 +/- 0.05). So most of the benefit of the count model over replay comes from using expected
   backups over observed next-token distributions, not from the particular memory.
4. **Count beats SDM at matched bits, and SDM costs far more compute.** Count minus SDM is +0.074 +/- 0.022 over
   the grid and +0.069 +/- 0.062 in the dynamics-drift phase (borderline there, the interval barely excludes zero). At n_plan 20 the
   SDM needs about 117,000 approximate FLOPs per real step against about 2,100 for the count model, because every
   read compares all hard-location addresses.
5. **The gain over replay is largest at small planning budgets.** Count minus replay is +0.117, +0.094, +0.068 at
   n_plan 5, 20 and 50. Replay improves with planning (0.385, 0.424, 0.453) while the count model is nearly flat
   (0.503, 0.518, 0.521).

## Hypotheses

| id | status in this first pass |
|---|---|
| E5-H1 (reward drift: any Dyna arm with a reasonable model beats Q-learning and replay) | **Supported against Q-learning and against replay with current rewards, not against `replay_sa`.** Count beats Q-learning by +0.29 and replay by +0.12 in the drift phase. The tie with `replay_sa` means the advantage is the expected backup, not the memory. The prediction that the gain shrinks as coverage grows was not tested. |
| E5-H2 (under dynamics drift, fast-adapting memories lose less than slow gradient models) | **Not tested.** No gradient model was built. Within count versus SDM, the dynamics-drift gap is +0.069 +/- 0.062, borderline. |
| E5-H3 (return tracks one-step KL, with overconfident models planning worse than KL predicts) | **Weak and mixed.** Pooled Spearman(KL, score) is -0.28 across the four model arms (lower KL, higher score), but the sign inside arms is inconsistent (count -0.30, SDM +0.21, noaction +0.66, `replay_sa` -0.62). SDM has the worst ECE (0.195 against 0.069 for count) and a lower score, which fits the direction of the hypothesis, but SDM also has different KL and compute, so this is not a clean test. |
| E5-H4 (Dyna advantage over replay appears only at large n_plan) | **Contradicted in this setup.** The advantage is largest at n_plan 5 and shrinks as replay catches up. |
| E5-H4b (the action input does the planning work) | **Supported strongly.** Count minus noaction is +0.38, +0.33, +0.31 at c = 0.3, 0.6, 0.9. Note it does not grow with c here, contrary to the simple expectation. |
| E5-H5 null (`dyna_count` ties every other memory in every cell) | **Not supported against SDM and replay; small against `replay_sa`.** The null that the choice of memory does not matter is rejected for SDM, and count beats an uncompressed table by a small but non-zero +0.029 +/- 0.019. |

Stop rule check, from the spec: replay does not match the best Dyna arm across the grid (count minus replay is positive
at every n_plan), results were not re-run under hyperparameter changes (so "flip under hyperparameter changes" is
untested), and compute is accounted by an analytic approximation. No stop condition is met, and the stability condition
is untested.

## What this does not show

* **No neural memories.** The comparison that motivated E05 (gradient models versus counts and SDM as world models)
  is the part not built. The SDM here is the generic `sdm`, not the pilot's `sdm_snn` stub, and must not be reported as
  the SDM/SNN result.
* **No tuning.** All arms use shared fixed Q-learning settings (alpha 0.3, epsilon 0.1) and memory defaults. The count
  model's lead may partly reflect how well its defaults suit a 64-state source. SDM defaults (decay 0.999, 10 percent
  active locations, 8-bit codes) were not searched.
* **A tiny state space.** 64 states by 4 actions lets an uncompressed table fit in memory. At 4096 states the
  `replay_sa` table would cost far more than the count model's capped table, and the memory-budget argument for a
  compressed model would then have teeth. This first pass cannot say what happens there.
* **Visited-only planning is a design choice that dominates.** The coverage gap (0.18) is larger than any gap between
  memories. An agent that plans over unvisited pairs with a generalising model (SDM could in principle) is not
  evaluated, and might change the ranking of the memories.
* **Reward knowledge is shared and tabular.** `R_hat` is the last observed reward per (s, next token) in every arm. A
  memory that also generalised the reward function is a different experiment.
* **The behaviour return includes exploration.** epsilon is 0.1 throughout, so scores are below what the greedy policy
  would earn.
* **Rough statistics.** Paired intervals over 15 to 45 MDPs, not corrected for multiple comparisons, with MDPs reused
  across n_plan. The two small gaps that matter for the story (model headroom +0.040 +/- 0.025 and count minus `replay_sa`
  +0.029 +/- 0.019) have intervals that exclude zero but are small next to the coverage gap, and the intervals are rough.
* **Severity at 1.0 uses 3 seeds** against 5 at 0.5, so the severity table mixes sample sizes.
* **Not a claim about evolution or about "simulating" as a cognitive stage.** The Bennett framing motivated the design
  and the experiment stands without it.

## What to do with it

The honest read is that the design is worth continuing for one reason and not for another. The reason to continue is
that the action-conditioning interface works, the exact oracle works, and the first pass found a large effect that was
not in the spec (coverage of the Q table) and a clean one that was (the action input). The reason not to read much into
the memory comparison is that the question E05 was designed to answer, whether LSTM and Transformer world models plan
differently from counts, has not been touched. The next steps in priority order: run E01 and E02 with the neural models
on a machine with PyTorch, add `predict_at(x_context, a)` to the LSTM and Transformer adapters, scale the MDP to 4096
states so budgets bind, and add a coverage-aware planning arm.
